# HUB — техническое задание (семестр)

Веб-сервис коллективной разметки датасетов компьютерного зрения.

Сделать нужно **только то, что описано в этом файле**. Чего здесь нет — в сдачу не входит и в интерфейс не добавляется.

---

## 1. Результат

Работающий веб-сервис (клиент + сервер), в котором можно:

1. Зарегистрироваться и войти (email + пароль, вход через Яндекс ID).
2. Загрузить изображения и/или уже существующую разметку (картинка + txt).
3. При загрузке привести кадры к формату, с которым работает YOLO: если исходник не jpeg/png, платформа **сама конвертирует в `.jpg`**. Исходное имя (stem) сохраняется.
4. Собрать кадры в **датасет**: список классов, split train / val / test.
5. Смотреть галерею, фильтровать по split, открывать кадр.
6. Размечать в браузере геометрию: **Bounding Box**, **OBB**, **Polygon**.
7. Работать нескольким людям над одним датасетом: роли, блокировка кадра, история, приёмка разметки.
8. Выгрузить датасет **одним ZIP** в формате YOLO — на выбор **одна из двух раскладок папок** (см. §4.5).

Документация к сдаче: README (как поднять), описание контракта данных, OpenAPI, Docker Compose.

## 2. Пользователи и роли

Внутри датасета три роли.

| Роль | Галерея и просмотр | Редактор | Приглашения | Экспорт | Удаление датасета / сэмплов |
|------|--------------------|----------|-------------|---------|-----------------------------|
| Владелец | да | да | да | да | да |
| Разметчик | да | да | нет | нет | нет |
| Наблюдатель | да | нет | нет | нет | нет |

Права проверяются **на API**, не только скрытием кнопок.

Владелец приглашает участников по email или логину. У приглашённого в кабинете список «Доступные мне датасеты».

## 3. Сущности

| Сущность | Что это |
|----------|---------|
| Пользователь | Аккаунт |
| Датасет | Проект: кадры, классы, настройки |
| Сэмпл | Один кадр + разметка + split + статус |
| Объект разметки | Класс + геометрия (box / obb / polygon) |
| Конфиг классов | `data.yaml` (порядок имён = индекс в txt) |
| Участие | пользователь × датасет × роль |
| Событие истории | кто, что, когда |

Датасет имеет **один** тип задачи (`task`):

- `detect` — только Bounding Box  
- `obb` — только повёрнутые рамки  
- `segment` — только Polygon  

Смешивать типы геометрии в одном датасете нельзя.

## 4. Контракт данных

### 4.1. Классы — `data.yaml`

При создании датасета: загрузить свой yaml **или** сгенерировать минимальный и править список классов в интерфейсе.

```yaml
path: .
train: images/train
val: images/val
test: images/test
names:
  0: object_a
  1: object_b
```

Для раскладки «прямая» (§4.5) поля `train` / `val` / `test` указывают на соответствующие пути этой раскладки. При экспорте yaml должен **совпадать** с выбранной раскладкой.

Переименование класса не должно молча сдвигать индексы уже размеченных объектов: предупреждение и явное подтверждение.

### 4.2. Геометрия: только через `acmenra-cv`

Контракт объектов **не придумывается**. Чтение и запись разметки (`.txt` / обмен с редактором) делаются через Python-библиотеку **`acmenra-cv`**.

Документация: [docs.acmenra.studio](https://docs.acmenra.studio) — модуль `instance`, примитивы `Box`, `OBB` (`Obb`), `Polygon`. Координаты нормализованы в `[0.0, 1.0]`.

Правила:

- свой парсер/сериализатор строк YOLO **писать нельзя** (ни «почти как Ultralytics», ни «свой JSON на диск»);
- импорт txt, экспорт txt, проверка координат — вызовы `acmenra-cv`;
- фронт рисует то, что API отдал после разбора библиотекой, и сохраняет через API, который снова прогоняет геометрию через библиотеку;
- если бэкенд не на Python — для импорта/экспорта поднимается Python-сервис в том же `docker compose`, который внутри использует `acmenra-cv`. Второй контракт геометрии не заводится.

Пакет и точную версию на старте выдаёт заказчик (pip / wheel). В `docs/DATA_CONTRACT.md` — не «мы выбрали формат OBB», а: версия библиотеки, какие функции/классы вызываете, примеры входа-выхода.

Имя файла разметки = имя кадра: `img001.jpg` ↔ `img001.txt`.

Кадр без объектов: **пустой txt** (файл есть, внутри пусто). Так для всех split и обеих раскладок.

### 4.3. Split

У каждого сэмпла: `train` | `val` | `test`.  
Вкладки галереи: All / Train / Val / Test.

### 4.4. Изображения

На входе допускаются обычные фотоформаты (jpeg, png, webp, bmp, tiff, heic/heif и т.п.).

**Правило стандартизации:** в хранилище датасета и в экспорт попадают кадры, которые YOLO принимает без сюрпризов.

- jpeg и png можно оставить как есть (png — допустим).  
- всё остальное, включая `.heic` / `.heif` / `.webp` / `.bmp` / `.tiff`, **конвертировать в `.jpg`** при загрузке.  
- stem имени не менять: `DSC_0001.HEIC` → `DSC_0001.jpg`.  
- если рядом лежал `DSC_0001.txt` — он остаётся привязан к новому jpg.  
- ошибка конвертации одного файла не откатывает всю пачку: этот файл в отчёте загрузки, остальные проходят.

В README указать фактически поддержанный список входных форматов. HEIC обязателен к попытке конвертации (через стандартные библиотеки/утилиты в контейнере). Если в среде конвертер heic недоступен — это блокер, а не «потом».

### 4.5. Две раскладки YOLO (импорт и экспорт)

Платформа понимает и отдаёт **оба** варианта. При экспорте владелец **выбирает раскладку**. При импорте zip система определяет раскладку сама.

**Прямая** (split снаружи):

```
dataset_name/
  data.yaml
  train/images/...
  train/labels/...
  val/images/...
  val/labels/...
  test/images/...
  test/labels/...
```

**Обратная** (тип снаружи):

```
dataset_name/
  data.yaml
  images/train/...
  images/val/...
  images/test/...
  labels/train/...
  labels/val/...
  labels/test/...
```

В `data.yaml` пути соответствуют выбранной раскладке.

**Состав zip по умолчанию:** только сэмплы со статусом «Принято».  
Отдельный тогл «экспортировать все, кроме „На доработку“» — можно, не обязательно. Если нет тогла — строго только «Принято».

### 4.6. Импорт

- один файл изображения;
- папка (в т.ч. с вложенными txt рядом с кадрами);
- zip в **прямой** или **обратной** раскладке.

Битый txt: сэмпл создаётся, разметка пустая, на карточке видна ошибка парсинга. Остальные файлы пачки не откатываются.

## 5. Статусы сэмпла и блокировка

```
Не размечен → В работе → На проверке → Принято
                 ↑            ↓
                 └── На доработку
```

Других статусов не вводить.

**Soft Lock.** Открытие редактора ставит статус «В работе» и плашку «В работе у @пользователь». Пока блокировка жива, другой пользователь только просматривает кадр и **не может сохранить** поверх. TTL 15–30 минут, при активности продлевается. Закрытие редактора снимает lock. Владелец может снять lock принудительно; это пишется в историю.

**Ревью.** Разметчик отправляет кадр «На проверку». Владелец видит очередь таких кадров: «Принято» или «На доработку» (комментарий желателен). Фильтр галереи по статусу. Принятый кадр разметчик не редактирует, пока владелец не снимет статус.

## 6. Функциональные требования

### 6.1. Аккаунт

- регистрация и вход: email + пароль;
- вход через Яндекс ID (ключи выдаёт заказчик; пока ключей нет — работает почта, OAuth подключается следом);
- профиль: отображаемое имя, выход;
- пароли не хранятся открытым текстом;
- повторный вход через Яндекс не создаёт второго пользователя с тем же аккаунтом.

Восстановление пароля желательно. Если нет — строка в Known limitations.

### 6.2. Датасеты

- создание, список «мои» и «доступные мне»;
- имя, описание, приватность: доступ только владельцу и приглашённым;
- выбор task (`detect` / `obb` / `segment`);
- yaml классов: загрузка / генерация / правка в UI;
- удаление сэмпла (владелец).

Два датасета не смешивают кадры. Чужой датасет недоступен по прямой ссылке/ID.

### 6.3. Загрузка и галерея

- файл и папка, drag-and-drop;
- конвертация в jpg по §4.4;
- карточка сэмпла: превью, число объектов, split, статус;
- пагинация;
- вкладки All / Train / Val / Test;
- hover на карточке: в покое исходник, при наведении — превью с наложенной разметкой;
- у сэмпла прямая ссылка на файл кадра и на txt (если разметки нет — пустой txt или честный 404, поведение одно на проект и описано).

Для превью в галерее разметка может быть вшита в растровую миниатюру на сервере, чтобы сетка не парсила txt в каждом браузере.

### 6.4. Инспекция (просмотр без правки)

Клик по карточке — полный кадр.

- векторная отрисовка масок поверх оригинала (Canvas или SVG);
- зум и пан;
- тумблер показать/скрыть маски;
- панель: разрешение, размер файла, число объектов по классам, статус, split;
- блок «История»;
- в этом режиме геометрию сдвинуть нельзя.

Крупный кадр должен открываться. Зум должен оставаться пригодным для работы (ориентир: FullHD, десятки объектов на кадре, без «слайдов»).

### 6.5. Редактор

Вход из инспекции (владелец и разметчик).

- создание и правка геометрии своего task;
- выбор класса объекта из списка датасета;
- удаление объекта;
- undo/redo в пределах сессии кадра;
- явное сохранение и/или автосейв с индикатором;
- после перезагрузки страницы маски те же;
- при сохранении координаты нормализуются в 0..1 и не уезжают в мусор;
- хоткеи описаны в `docs/KEYBOARD.md` (минимум: сохранить, undo, тумблер масок, следующий кадр).

Поведение мыши и клавиш — привычное для разметки (как в общеизвестных редакторах разметки), без уникальных жестов «с нуля».

### 6.6. История

- у сэмпла: кто загрузил, когда;
- у объекта: создатель и последний редактор, время;
- лента в инспекции: загрузка, сохранение, смена статуса, lock, смена класса.

Не требуется хранить diff каждого узла полигона. Нужны факты действий.

### 6.7. Экспорт

Кнопка у владельца. Выбор раскладки zip (§4.5). Прогресс/понятная ошибка, если архив не собрался. Скачанный zip пригоден к обучению YOLO **без ручной правки txt и yaml**.

## 7. Нефункциональные требования

- OpenAPI (Swagger) бэкенда.
- `docker compose up` поднимает веб, API, БД и хранение файлов.
- Основная поверхность — десктоп. Мобильная вёрстка не требуется.
- Ошибки в UI — понятные сообщения, на русском.
- Пустые экраны: нет датасетов / нет кадров / нет «на проверке» / нет инвайтов — осмысленный текст, не сырая заглушка.
- Безопасность: пароли хэшируются; нет IDOR (чужой датасет по ID); XSS в именах классов и комментариях не исполняется.

Стек команда выбирает сама при условии, что закрыты требования этого файла. Рекомендация: веб на TypeScript, API с OpenAPI, PostgreSQL, файлы в volume Docker.

## 10. Сценарии сдачи

Прогон на чистом `docker compose up`.

**A. Команда**  
Владелец создаёт датасет и классы → загружает папку кадров (часть в не-jpeg, проверка конвертации) → приглашает разметчика → разметчик размечает и отправляет на проверку → второй пользователь не перезаписывает тот же кадр → владелец принимает / возвращает → экспорт ZIP в выбранной раскладке.

**B. Соло**  
Регистрация → импорт папки или zip с готовыми txt (одна из раскладок) → правка нескольких масок → split → скачивание zip в **другой** раскладке, чем импорт → yaml и txt валидны.

**C. Наблюдатель**  
Видит кадры и инспекцию. Не сохраняет разметку. Не экспортирует. Запрет проверяется запросом к API, не только UI.
